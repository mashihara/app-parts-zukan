# アプリ部品図鑑

スマホアプリの部品58個（ステータスバー・ナビゲーションバー・タブバー・ボトムシート・アクションシート・アラート・スナックバー・スワイプアクション・プルして更新・セグメンテッドコントロール・ピッカー・リストのセル・プッシュ通知など）の正式な名前・意味・使いどころ・AIへの頼み方の例と、まぎらわしい名前の見分け方をまとめたサイトです。名前は iOS（Human Interface Guidelines）と Android（Material Design）の呼び方にそろえ、もう一方の呼び方は別名に入れています。

Webの画面の部品（ヘッダー・モーダル・ダイアログなど）は姉妹サイトの UI部品図鑑（https://mashiharalab.dev/ui-parts-zukan/llms.txt ）を使う。

## 受け取った物ごとの動き方

1. **「アプリ部品図鑑で調べたアプリの部品の名前です」で始まる文が貼られた**: 並んだ部品を、書かれた意味どおりに使って作る。最後に書き足された依頼（作りたい物）に従う。
2. **リンクが貼られた**: リンクと同じ場所の `llms.txt` を読む。`pick` の id が使いたい部品（選んだ順）。部品ごとの詳細は `api/v1/parts/<id>.txt`、全データは `api/v1/catalog.json`。
3. **名前が分からないと言われた**: `catalog.json` の `parts`（ja・en・aka・meaning）から候補を挙げ、`confusions` の見分け方を1行で添える。

## 守ること

- 部品は正式な名前で呼ぶ（「下から出てくるやつ」→ボトムシート／アクションシート／モーダル遷移のどれかを確かめる）。
- まぎらわしい名前は見分け方に従う（例：「元に戻す」が付くのはスナックバー、知らせるだけならトースト）。
- SwiftUI・Jetpack Compose・Flutter・React Native のどれで作るときも、部品の名前は同じ意味で使う。
- 作り終えたら、使った部品の名前を報告する。
